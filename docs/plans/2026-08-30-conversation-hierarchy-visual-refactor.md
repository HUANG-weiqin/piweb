# 会话层级视觉重构

`status: implemented`

## 问题

协作组已经正确表达“根任务 + Agent 成员”，但根会话、独立主会话和成员仍复用近乎相同的字号、底色与行形态。连接线只能在仔细阅读后提供线索，用户无法在扫视侧栏时先看到任务层，再看到执行层。

这不是会话模型问题，而是展示层把不同导航层级压成了同一种视觉权重。

## 支持的边界

- `rootConversationId` 仍是唯一分组事实；客户端不从 `createdBy` 递归猜测。
- `ConversationActor`、run、inbox、删除级联、排序、展开状态和导航命令全部不变。
- 根、成员和独立会话继续复用同一个 `ConversationRow`，只增加由分组投影调用点明确给出的展示变体。
- 不新增协议字段、持久状态、会话类型或图标依赖。

本设计替代上一版“各层使用同一行样式、组容器不覆盖背景”的视觉限制，但不改变其数据与交互约束。

## 美学方向

采用克制的桌面工作台风格：暖中性主层、低饱和冷色执行层、少量边框和稳定排版。层级必须同时由**容器、缩进、字号和色调**表达，不能只靠一个徽标。

| 层级 | 结构 | 排版 | 色彩 |
|---|---|---|---|
| 主任务 | 协作组外框内的首行，带“主任务”标签 | 14px 高字重标题 | 暖中性主表面、实心层级点 |
| 独立主会话 | 一级独立卡片，带“主会话”标签 | 与主任务同级 | 暖中性主表面、空心层级点 |
| 协作 Agent | 展开后进入连接轨道和“协作 Agent”分区 | 12px 中等字重、元信息再降一级 | 低饱和冷色浅底与冷色选中线 |

主任务与独立主会话同属一级导航，所以保持相同标题尺度；二者通过容器关系和实心/空心标记区分。Agent 成员不再伪装成另一张一级卡片。

## 状态颜色

身份层级和运行状态是两个观察维度：

- 冷色只表达“协作 Agent 执行层”；
- 绿色只表达 running；
- 黄色只表达 queued / waiting / attention；
- 红色只表达 cancelling / danger；
- 状态色集中在状态图标和必要的 attention 提示，不再让整行文字随 activity 变色。

这样用户先识别“它是谁”，再识别“它现在怎样”。

## 交互与可访问性

- 会话按钮、disclosure、改名和删除仍是独立按钮，不产生嵌套交互。
- 现有 `aria-current`、`aria-expanded`、`aria-controls` 和状态 `aria-label` 保持不变。
- “主任务 / 主会话 / 协作 Agent”提供文字冗余，不把颜色作为唯一层级线索。
- 成员行仍保留完整标题、角色、短句柄、最后活跃时间和生命周期动作。
- 所有选择、排序、自动展开、空闲成员 reveal 和 action gate 语义不变。

## 响应式与主题

- 继续支持 240–640px 桌面侧栏和现有 600px 以下移动 overlay。
- 标题与摘要仍使用 ellipsis，成员容器不得产生横向滚动。
- 颜色只由现有 `panel / intent / line / status` token 混合得出，暗色模式不维护第二套值。
- 过渡沿用 120–160ms，并继续服从 `prefers-reduced-motion`。

## 验收

1. 不读文字内容也能从卡片外框、成员色块和缩进识别一级任务与执行成员。
2. 主任务与独立主会话拥有相同的一级标题权重；成员标题明显更小、更紧凑。
3. 当前成员以冷色选中线标识，当前主会话仍使用中性主选中线。
4. running / waiting / attention 等状态仍可辨认，但不会覆盖身份层级。
5. 键盘、移动端、暗色模式及窄至 240px 的侧栏不丢失操作或产生横向溢出。
6. 不增加任何 wire、持久化或运行时概念。
